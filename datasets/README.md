# PSyllabus 数据目录

## 已整理的文件

- `archives/cqt5.zip`：原始 CQT 压缩包，保留不删除。
- `archives/mid.zip`、`archives/pianoroll5.zip`：保留原始压缩包，暂不解压；当前 audio-only 基线不依赖它们。
- `metadata/new_clean_data.json`：原始曲目元数据与标签，7,901 条记录。
- `metadata/split_audio.json`：作者提供的 5 折划分，保持原样。
- `cqt/`：已解压 7,901 个 `.bin` 文件，去掉 ZIP 内多余的 `cqt5/` 包装层，文件名未修改。
- `audio/`：目前没有原始音频；元数据中的音频链接不等于音频文件。
- `features/`：尚未生成 CQT 统计量或节奏特征。
- `splits/`：为本项目的作曲家隔离划分预留，目前尚未生成。
- `inventory.json`：文件大小、原始文件校验值、解压检查与官方划分检查的机器可读清单。

## 读取提示

元数据是以曲目名称为键的 JSON 对象。解压后 CQT 文件的文件名（去掉 `.bin`）与元数据键完全匹配，可据此关联；不要根据目录顺序拼接标签。

主难度字段 `ps` 的实际值为字符串 `0` 至 `10`，读取时显式转成整数。`composer` 可用于初步作曲家分组。文件键匹配不等于已经检查所有同曲不同录音、乐章与作品之间的关系，训练前仍需复核。

**CQT 文件是 `.bin`，不是 `.npy`。** 抽查头信息显示其包含 pickle 序列化的 NumPy 数组，不能直接假设为 NumPy 的 `.npy` 格式。本次只核验文件头与完整性，没有执行 pickle 反序列化或检查全部数值内容。后续仅对已确认可信来源的文件使用对应加载方法；pickle 可能执行代码，不能加载不可信文件。

节奏特征仍需要原始音频。MIDI/piano roll 仅作为下载素材保留，未加入 proposal 的 audio-only 主实验，也未生成替代音频。

## 重要：官方划分不是作曲家隔离划分

按元数据中 `composer` 字符串精确匹配，5 折都存在跨集合的作曲家重叠。例如第 0 折：

- train / validation / test 分别为 4,736 / 1,576 / 1,589 条。
- 三个集合之间的曲目键无重叠，均可在元数据中找到。
- train 与 test 有 378 个重叠作曲家字符串。

因此，`metadata/split_audio.json` 只能作为原始参考，**不能直接声称它满足 proposal 中的 composer-disjoint 要求**。本次没有改动官方划分，也没有自行生成新的实验划分；后续需单独设计并冻结到 `splits/`。

## 已执行校验及边界

- 3 个 ZIP 与 2 个 JSON 的 MD5 均与发布页给出的值一致。
- 归档前后 SHA-256 一致，原始下载文件内容未改动。
- CQT 解压前检查路径安全和可用空间，拒绝覆盖已有文件。
- 所有 7,901 个解压文件均回读检查大小和 CRC，通过。
- CQT 文件键与元数据键完全对应；两份 JSON 均能被严格解析。
- MIDI、piano roll 只核对压缩包完整文件的 MD5，未解码其内部内容。
- 未试听或下载原始音频，未验证全部 CQT 数值与音乐内容，未生成特征或训练模型。

MIDI 与 piano roll 暂时不解压，可避免与当前主线无关的磁盘占用。原始文件、解压数据和特征缓存均被 `.gitignore` 排除；小型说明、校验清单及后续项目划分可纳入 Git。
